# S17 pacing and contextual hints

S17 depends on [accepted S16](https://github.com/2dshligang/last-known-state-the-legacy/pull/29). S01 remains API 1.0 and the S16 disk schema remains v2. Diagnostics are per session, in memory and local. New Game and Continue begin new diagnostic segments. There are 64 recent event slots, seven chapter counters and one consecutive-failure hint streak. The player never needs a network connection. Only stable gameplay IDs, result codes and known resource decisions enter records. Release code does not write a console trace or export files.

## Developer 1 binding

1. After a deliberate action, read `bootstrap.Current.Pacing.TryGetHint(subject, out key)` and resolve the returned `hint.pacing.*` key through the existing English content catalog. Show this beneath the regular feedback shortly after the third matching failure. Use the actual target ID for quest and sample actions and inspected ECHO clues, `EchoInvestigation.SequenceSubject` for order submission, `StationResearch.ReportId` for the report, and `StationPacing.PowerDecision` or `StationPacing.FoodDecision` for resource controls. The hint supplies text only.
2. Quest targets, ECHO collection and order submission, sample record/collect/analyze/review, power allocation, food choice and report submission already record their outcomes. If the UI refuses a deliberate press before calling a tracked action, use `RecordBlockedInteraction(target, reason, messageKey)` once with the displayed reason. Never record prompt previews, hover, drawing, or both this fallback and the action for the same attempt.
3. Capture `Pacing.CaptureChapters()`, `CaptureEvents()` and `ReportRetries` after a QA run before restarting or continuing. For a deliberate blocking wait, set `SetPacingWaiting(true)` while the player has no other objective to pursue and clear it on exit. Pending lab or communications work can overlap other activity. Keep existing reading pause and player focus calls wired. Chapter buckets use the session clock. Reading takes precedence over marked waiting. The Unity clock excludes menu pause. Existing power pause includes focus loss, so exclude application switches from a human timing session.
4. Run the tests of `StationPacingTests` and verify one visible hint in the installed scene after HUD binding. The stable diagnostic API is `StationPacing.ApiVersion == 1`. Developer 1 owns the HUD and QA views. Developer 2 owns the timing schema and message keys.

See [the pacing sheet](S17-Pacing.md) for the automated measurements and first-time playtest fields.
