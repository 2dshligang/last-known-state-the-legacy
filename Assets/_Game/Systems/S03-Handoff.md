# S03 station progress

S03 uses S01 API 1.0 and the [accepted S02 bootstrap](https://github.com/2dshligang/last-known-state-the-legacy/pull/5). Systems depends on Quests, and Quests depends on Contracts. The registry uses stable IDs and has no scene name dependencies.

1. Developer 1 binds authored targets to the IDs in `StationQuests.RequiredStages`: `quest.arrival`, `quest.safe-power`, `quest.echo-evidence`, `quest.sampling`, `quest.analysis`, `quest.report`, `quest.ending`. Bind a reachable `target.power-recovery` after arrival. Pass the authored IDs to `ValidateReachability` and resolve missing targets before playtesting.
2. Call `SessionBootstrap.RestartWithQuests` with the actual catalog, existing target factory and domain callbacks. The readiness callback is a pure query. Return Applied only when the responsible service confirms the milestone, InsufficientResources for an unsafe allocation, and EvidenceInsufficient for incomplete evidence. For the ending, require domain approval and route the deliberate photograph interaction to the target. The final narrative text remains `Dad... I did it.`
3. Read availability with `Read(actor.alexei)`. Submit `action.confirm` only for a deliberate interaction. UI open and ECHO playback perform reads only. The power recovery target accepts `action.recover-power`. The supplied recovery callback must restore a safe allocation or return the authoritative failure reason. Developer 2 owns this integration in S04. Keep recovery reachable from the safe return path.
4. Read `Current.Quests.Snapshot` and subscribe through `IQuestService`. Treat Available as prerequisite order and Read as live domain readiness. Keys map to English UI text. `action.confirm` means “Confirm”. `action.recover-power` means “Restore a safe power allocation”. Keys under `quest.result` use applied (“Step complete”), completed (“Already complete”), prerequisite (“Finish the previous step first”), resources (“Restore resources and try again”), evidence (“More evidence is needed”), invalid-action (“This action is unavailable here”) and unavailable (“Unavailable”).
5. Capture the quest checkpoint through `Current.CaptureQuestCheckpoint()`. Restore it alongside the domain state using RestartWithQuests. Only an ordered prefix is valid. Pass no checkpoint for New Game. The durable schema and storage adapter are S16 work.

Run LKS.Systems.Tests in Unity EditMode. For scene acceptance, verify each physical binding and take the recovery path after a rejected allocation. Developer 1 owns the scene, while Developer 2 owns the power, ECHO, science and report rules that provide readiness. The tests use explicit fixtures for those dependencies.
